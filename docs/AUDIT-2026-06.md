## Security

- 🔴 **ACTION REQUIRED — проверить, что RLS применён к живой базе.**
  Миграция `supabase/migrations/20260530000000_enable_rls.sql` существует и
  покрывает users / projects / project_members / tasks / expenses / payments
  (payments immutable с клиента). Но её шапка прямо говорит: политики
  реконструированы из кода, НЕ из живой схемы, и требуют ревью перед
  применением. Без применённого RLS любой обладатель anon key пишет в чужие
  проекты в обход server actions. Проверка: Supabase Dashboard → Database →
  Tables → колонка RLS, либо SQL:
  `select relname, relrowsecurity from pg_class c join pg_namespace n on n.oid=c.relnamespace where n.nspname='public' and relkind='r';`
- ✅ **FIXED 2026-06-10** — `src/app/actions/payments.ts`:
  `stripe.transfers.create` к connected-аккаунту теперь за фичефлагом
  `STRIPE_PAYOUTS_ENABLED=true`; по умолчанию payout только записывается в
  БД. Реальное движение денег к субподрядчикам — marketplace-территория
  Stripe Connect: без полноценного Connect-онбординга (KYC, compliance) это
  главный риск бана аккаунта. Не включать флаг, пока Connect не настроен.
- ✅ Server actions проверяют auth, роль и ownership вручную — корректно,
